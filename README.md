# เปรี้ยว จูนเนอร์ Smart Gauge v1.0.19 — ESP32 CYD (รถยนต์ ELM327 + Honda K-line + ซิงค์ Jet Honda APP)

มาตรวัดอัจฉริยะบนจอ ESP32-2432S028R (320x240) มี 2 โหมด: **รถยนต์** (ELM327 ผ่าน Bluetooth — AFR log สำหรับเบนซิน, CRP log สำหรับดีเซล) และ **มอเตอร์ไซค์ Honda** (อ่าน ECU ตรง ๆ ผ่านบอร์ด K-line ที่ปลั๊ก 6 พิน) — และใช้สาย USB ซิงค์ค่าสด/ตาราง log กับแอป **Jet Honda APP** ได้ทั้งสองโหมด (Wi-Fi มีเฉพาะในโหมดอัปเดต SETUP → UPDATE)

## ของใหม่ใน v1.0.19 (หน้าจอเกจหน้าตาเหมือนแอป Jet Smart Gauge v1.6.12)
- **หน้า Dash แบบเดียวกับแอป**: วงรอบ (tacho) เป็น **48 ช่องแบ่งด้วยร่องบาง ๆ** เหมือนแอป (ไม่มีแสงฟุ้งแล้ว) — ติดทีละช่อง เขียว → เหลือง → แดงที่จุดเปลี่ยนเกียร์ (โหมดสีปิดอยู่ใช้สีธีม แล้วเป็นสีแดงเมื่อเกินจุดเปลี่ยนเกียร์) · ช่องที่ยังไม่ติดเป็นสีพื้นเข้ม
- **แถบใต้วงรอบ = Throttle** เหมือนแอป (ชื่อ + ค่า % ทศนิยม 1 ตำแหน่ง + แถบ) แทนแถบ "ค่าถัดไป" เดิม — **การแตะวงรอบ** ยังสลับค่ากลางวงรอบได้เหมือนเดิม (ความเร็ว → แรงดัน CRP / ระยะทริปใน K-line → AFR) แต่ **แตะแถบล่างไม่สลับแล้ว** · ค่า CRP โวลต์ (ดีเซล) ดูได้ที่กลางวงรอบหรือหน้า Data
- **ช่องค่า 6 ช่องของ Honda K-line เป็นชุดเดียวกับแอป**: น้ำ, อากาศเข้า, MAP | แบตเตอรี่, **Injector (ใหม่)**, ไทมิ่ง (คันเร่งย้ายไปอยู่แถบใต้วงรอบ) — คนที่เคยเลือกช่องเองไว้ (แตะช่อง) ยังได้ช่องที่เลือกเหมือนเดิม
- **ชื่อแท็บเหมือนแอป**: `Data` → **`Grid`**, `Codes` → **`DTC`** (ภาษาอังกฤษ; ภาษาไทยยังเป็นคำไทยเดิม) · แท็บอื่นคงเดิม: Dash / Graph / Trip / Setup
- **ยังไม่เหมือนแอปตรงไหน (ตั้งใจ)**: ไม่มีกล่อง **GEAR** (เกจไม่มีข้อมูลอัตราทดเกียร์ แอปเองก็แสดง "–" กับรถยนต์), ไม่มีหน้า **Drag** (เกจไม่มี GPS), หน้า AFR LOG ยังวางตาราง RPM เป็นแนวนอน (แอปวางเป็นแถวแนวตั้ง — ตารางเก็บแบบเดียวกัน ซิงก์กันได้ตามเดิม), หัวจอยังเป็นชื่อรถ + เวอร์ชัน (แอปมีชิปสถานะ + นาฬิกา) และหน้า Setup เป็นรายการปุ่มแบบเกจ
- **ทดสอบแล้วบนคอมพิวเตอร์ (ไม่ใช่บอร์ดจริง)**: เทสต์เฟิร์มแวร์เดิมผ่านครบ (314 + 58 ข้อ) + ชุดตรวจพิกเซลใหม่ 10 ข้อ (ช่องวงรอบมีร่อง, สีเขียว, ช่วงเปิดด้านล่างว่าง, แถบ Throttle เต็ม/ว่าง, แตะแถบไม่สลับ, ชุดช่อง K-line, ชื่อแท็บ) · พรีวิว 237 ข้อ
- ⚠️ **ยังไม่ได้ทดสอบกับบอร์ด CYD จริง** — ดูความคมของร่องวงรอบบนจอจริงอีกครั้ง (ร่องกว้างราว 0.7 พิกเซล) · ความถี่การอ่านค่าบนหน้า Dash เพิ่ม PID คันเร่ง (0x11) เข้ากลุ่มอ่านเร็วเสมอ (แทน CRP ที่แถบเดิมขอ)

## ของใหม่ใน v1.0.18 (โหมด DEMO กลับมา — เอาไว้เทสบนโต๊ะโดยไม่ต้องต่อรถ)
- **เปิดที่ไหน**: SETUP → **MORE** (SETUP 2) → ปุ่ม **DEMO** (แถวปุ่มล่างสุด ฝั่งขวา; ปุ่มใน SETUP 2 จัดเป็น 2 แถว และแถวของการตั้งค่าเตี้ยลงเป็น 27 px เท่าหน้า SETUP) — กดอีกครั้งเพื่อปิด ใช้ได้ทั้งโหมดรถยนต์และโหมด K-line
- **ระหว่าง DEMO**: เกจจำลองรถเบนซินคันหนึ่ง (ชื่อหัวหน้าจอ `MAZDA 2`; ใน K-line เป็น `HONDA BIKE`): รอบ/ความเร็ว/น้ำ/น้ำมันเครื่อง/แบต/AFR/โหลด/คันเร่ง/MAP/ไทม์มิ่ง/หัวฉีด และแรงดันรางหัวฉีด (CRP) ที่ขยับตามรอบ จึงเทสหน้า CRP/AFR log ได้ (เลือกรุ่นดีเซลในหน้า VEHICLE ถ้าอยากเห็นหน้าดีเซล) ทุก 40 วินาทีมีช่วงเร่ง 4 วินาทีไปถึงรอบเตือนเปลี่ยนเกียร์ (ค่าที่ตั้ง + 300 รอบ) เพื่อดูแถบรอบและการแจ้งเตือน; หน้ารหัส/ข้อมูล ECU/Freeze frame ใช้ข้อมูลจำลอง
- **ไม่ปนกับรถจริง**: แถบบนซ้ายขึ้น **DEMO สีเหลือง** ทุกหน้า (เลขเวอร์ชันอยู่ขวา) · **ไม่บันทึกลงแฟลช** — รีสตาร์ทเมื่อไรก็กลับมาที่รถจริงเสมอ (กันค่าปลอมค้างตอนขับ) · ไม่แตะการต่อ ELM327 / ไม่ปลุกสาย K เลย (K-line: ไม่เปิด UART) · **ไม่เขียนสถิติสูงสุดถาวร** (รอบ/ความเร็ว/อุณหภูมิ... ที่บันทึกไว้ในแฟลช) — ขยับเฉพาะสถิติของ "ทริปนี้" · ทริป/ล็อก AFR–CRP/กราฟ/สถิติทริป เริ่มสะอาดทั้งตอนเปิดและตอนปิด DEMO · ตอนปิด เกจกลับไปต่อรถจริงเอง · ไม่มีหน้าจอจอดรถและไม่มีแจ้งเตือน MIL ใน DEMO
- **ซิงก์กับแอปมือถือ**: ทดสอบแอปได้โดยไม่ต้องมีรถ — `LIVE` / `INFO` / `PIDS` / `TRIP` / `LOG_GET` / `GRAPH` ตอบด้วยค่าจำลอง และบิต demo (บิต 1 ของไบต์สถานะ ซึ่งมีอยู่เดิม) = 1, บิตลิงก์ ECU (บิต 0) = 0 เพื่อให้แอปแยกออกว่าเป็นของจำลอง · คำสั่งสาย K ของแอป (WAKE/TXRX) ยังทำงานจริงถ้าต่อ ECU แต่ค่าที่ผ่านไปไม่ถูกเอาไปแสดงบนจอระหว่าง DEMO
- **ทดสอบแล้วบนคอมพิวเตอร์ (ไม่ใช่บอร์ดจริง)**: ชุดเทสต์ DEMO ใหม่ **58 ข้อ** (ค่าจำลองอยู่ในช่วง, ช่วงเร่งถึงรอบเตือน, AFR/CRP/หัวฉีด, ไม่บันทึกลงแฟลช, สถิติถาวรไม่ขยับ, เริ่มสะอาดทั้งสองทาง, ปุ่มสองแถวของ SETUP 2 กดถูกทุกปุ่มทั้งสองโหมด, K-line บน obdTask จริง: 6 วินาทีแรกไม่มีการปลุก/ไม่เปิด UART แล้วปิด DEMO กลางทางต่อ ECU ได้เอง, ตาราง 0x11 ของแอปไม่ทับค่าจำลอง, โหมดรถ: ไม่ต่อ Bluetooth ระหว่าง DEMO และต่อใหม่ตอนปิด, ซิงก์ INFO/PIDS/TRIP ของแอป) + ชุดเดิม 314 ข้อและชุดเก่า 6 ชุดผลเหมือนเดิมทุกบรรทัด · ภาพหน้าจอเรนเดอร์จากเฟิร์มแวร์ (อังกฤษ/ไทย ทั้งสองโหมด) · พรีวิวเช็ก 231 ข้อ + 61 ช็อตตัวอย่าง (เพิ่มปุ่ม DEMO ใน SETUP 2 และช็อต DEMO รถยนต์ / Honda / หน้า K-line)
- ⚠️ **ยังไม่ได้ทดสอบกับบอร์ด CYD จริง** — โดยเฉพาะการสลับ DEMO ↔ รถจริงตอนมี ELM327 ต่ออยู่ (ตัดการเชื่อมต่อแล้วต่อใหม่); ถ้าเจออาการผิดปกติให้รีสตาร์ทเครื่อง (DEMO ปิดเอง)

## ของใหม่ใน v1.0.17 (เกจเป็นตัวกลางตัวเดียวที่คุยกับรถ — ส่งข้อมูลให้มือถือทาง Bluetooth LE ไม่ชนกัน)
- **เกจเป็นเจ้าของรถคนเดียว**: ELM327 (Bluetooth Classic หรือ BLE) และสาย K-line เป็นของเกจเท่านั้น — มือถือไม่เคยต่อกับรถ/อะแดปเตอร์เอง แต่ถามเกจ แล้วเกจตอบจากข้อมูลที่อ่านไว้อยู่แล้ว (PIDS / TRIP / INFO / CODES / GRAPH / LIVE / LOG_GET / SENSORS ไม่แตะสายและไม่แตะ ELM327 เลย)
- **ช่องทางมือถือ = Bluetooth LE แบบ Nordic UART** (service `6e400001-b5a3-f393-e0a9-e50e24dcca9e`, เขียนเฟรมที่ `…0002`, คำตอบมาเป็น notification ที่ `…0003`) — เป็นช่องที่แอป Jet Honda APP รู้จักอยู่แล้วในชื่อ **Smart Gauge (BLE / USB)** (เกจโฆษณาชื่อ `Jet Smart Gauge`): ใช้โปรโตคอลเฟรม MFB-LINK ตัวเดียวกับ USB ทุกอย่าง (รวมคำสั่งใหม่ของ v1.0.16) **ไม่ต้องแก้แอปเพื่อให้เชื่อมได้** (แอปจะใช้คำสั่งใหม่ได้ต่อเมื่อเรียกผ่าน `gauge_sync.js`)
- **ทำยังไงไม่ให้ชน**:
  - **วิทยุตัวเดียว ใช้ร่วมกัน**: BLE ของมือถือใช้สแตกบลูทูธชุดเดียวกับที่ต่อ ELM327 อยู่ (ไม่เปิดวิทยุตัวที่สอง, ไม่เปิด Wi-Fi) ขอให้มือถือเว้นช่วงการเชื่อมต่อ 30–50 มิลลิวินาทีเพื่อเหลือเวลาอากาศให้สาย Classic ไปยัง ELM327 และเกจ**ไม่ส่งข้อมูลเองเลย** — ส่งเฉพาะตอนมือถือถาม (ไม่มี streaming ที่ยิงต่อเนื่อง) · โฆษณาเฉพาะตอนไม่มีมือถือต่ออยู่
  - **สาย K**: คำสั่งที่แตะสาย (WAKE / TXRX / SENSE) ผ่าน BLE ใช้กติกาเดิมของ v1.0.15 — ระหว่างที่มือถือถือสายอยู่ เกจถอยจากสาย K 8–60 วินาที ไม่มีสองฝ่ายพูดพร้อมกัน; และถ้ามีไบต์จากมือถือรออยู่ เกจที่กำลังคุยสาย K จะเลิกกลางคันเพื่อไปตอบก่อน (เหมือนกับ USB)
  - **USB กับ BLE ใช้พร้อมกันได้**: บัฟเฟอร์ตัวแยกเฟรมแยกกันคนละชุด และคำตอบกลับทางเดียวกับที่ถามมา (ทดสอบสลับไบต์ของสองช่องทางทีละไบต์แล้วเฟรมไม่ปนกัน, คำตอบ BLE ไม่หลุดออก USB และกลับกัน)
  - **หน่วยความจำ**: ต้องมี heap เหลือ ≥ 100 KB ก่อนเปิดสแตก BLE (กรณียังไม่ได้เปิด) ถ้าไม่พอ เกจข้ามไป ไม่เสียระบบเดิม แล้วลองใหม่ทุก 20 วินาที · ถ้าโค้ด ELM327 รีสตาร์ทสแตกบลูทูธ เซิร์ฟเวอร์ของมือถือถูกสร้างใหม่เอง
  - **ปิดได้**: SETUP → MORE (SETUP 2) → ปุ่ม **BLE** มุมขวาบน (ค่าเริ่มต้น = เปิด; ปิดแล้วไม่เปิดสแตก BLE ตั้งแต่ต้น และถ้ามีมือถือต่ออยู่จะถูกตัดออก) — เผื่อบนบอร์ดจริงมีปัญหาเรื่องวิทยุ/หน่วยความจำ — หมายเหตุ: ปุ่มนี้มาแทนเลขเวอร์ชันที่เคยอยู่มุมขวาบนของหน้า SETUP 2 (เลขเวอร์ชันยังดูได้ที่หน้า UPDATE และแถบบนตอนยังไม่มีลิงก์)
- **ไอคอนซิงก์**: ขึ้นเมื่อมือถือ**ต่อ BLE อยู่** (นิ่งสีจาง) และหมุนสีสว่างตอนที่ถามข้อมูล เหมือนกับ USB; `INFO` เพิ่ม 2 บิต: flags บิต 6 (64) = มือถือต่อ BLE อยู่ตอนนี้, ไบต์ตั้งค่าบิต 7 (128) = สวิตช์ BLE เปิดอยู่ (`gauge_sync.js` → `bleConnected`, `settings.bleLink`)
- **ทำไมยังไม่มี Wi-Fi**: (1) แอปยังไม่มีช่องทาง Wi-Fi ไปหาเกจ (Wi-Fi ในแอปมีไว้ต่อ ELM327 เท่านั้น) จึงต้องเขียนฝั่งแอปใหม่ทั้งช่อง (2) ESP32 ใช้วิทยุเดียวกันระหว่าง Wi-Fi กับ Bluetooth — Wi-Fi พร้อมกับบลูทูธ Classic ที่ต่อ ELM327 อยู่ทำให้การโพลช้า/หลุด ซึ่งตรงข้ามกับเป้าหมาย "ไม่ชนกัน" (3) แฟลชของตัวเกจเหลือราว 420 KB เท่านั้น ส่วน Wi-Fi + เว็บเซิร์ฟเวอร์กินมาก — ถ้าจะทำจริง ควรทำเฉพาะโหมด K-line (ไม่มี Classic) แยกเป็นงานต่างหาก
- **ข้อจำกัดความเร็ว**: ยังไม่ได้ขอ MTU ใหญ่ (ค่า MTU เป็นค่าร่วมกับฝั่งที่ต่อ ELM327 BLE จึงไม่แตะก่อนทดสอบกับอะแดปเตอร์จริง) ดังนั้นแพ็กเก็ตละ 20 ไบต์: คำตอบยาว ๆ (TRIP / INFO ราว 250 ไบต์) ใช้เวลาราว 0.2–0.3 วินาทีต่อคำตอบ — `syncAll()` ทั้งชุด (~30 คำขอ) น่าจะหลายวินาที; ถ้ามือถือขอ MTU ใหญ่ เกจจะส่งแพ็กเก็ตใหญ่ขึ้นเองตามที่ต่อรองได้ (สูงสุด 180 ไบต์)
- **ทดสอบแล้วบนคอมพิวเตอร์ (ไม่ใช่บอร์ดจริง)**: ชุดเทสต์เฟิร์มแวร์ **314 ข้อ** (เดิม 234 + ใหม่ 80: เซิร์ฟเวอร์เริ่มเอง/โฆษณา/ต่อ/หลุด/เปิด-ปิดสวิตช์, PING/PIDS/TRIP/INFO/WAKE ผ่าน BLE ในโหมด K-line บน obdTask จริง, USB สลับไบต์กับ BLE, ขนาด notification 20/180 ไบต์, คำตอบ 250 ไบต์ถูกหั่นครบ, สแตกรีสตาร์ท, heap ไม่พอ, โหมดรถยนต์), ชุดทดสอบเก่า 6 ชุดผลเหมือนเดิมทุกบรรทัด, ตัวถอดรหัส JS, ภาพหน้าจอเรนเดอร์ (ปุ่ม BLE เปิด/ปิด, ไอคอนนิ่งตอนต่อแต่ยังไม่ถาม); พรีวิวเช็ก 217 ข้อ + 58 ช็อตตัวอย่าง (เพิ่มปุ่ม BLE ใน SETUP 2, ช็อต "มือถือต่อ BLE", ปุ่มจำลอง "Phone on BLE")

## ของใหม่ใน v1.0.15 (โหมดรถยนต์กลับมา + AFR log / CRP log + ซิงค์กับ Jet Honda APP ผ่าน USB)

  - **เปลี่ยนตามโหมดอัตโนมัติ**: โหมดรถ = หน้าหลักแตะกลางสลับ ความเร็ว → CRP volts → AFR, DATA 4 ปุ่ม (MAIN / ALL PIDS / CRP log / AFR log), ชุดค่า DATA เบนซิน/ดีเซล, หน้า CODES/มอนิเตอร์/CAN listen, แถว PROTOCOL และปุ่ม CRP sensor ใน SETUP 2. โหมด K-line = ชุดหน้าจอ Honda ของ v1.0.14 (หน้าหลักสลับ ความเร็ว ↔ ระยะทริป, DATA 16 ช่องชุด Honda, ไม่มี CRP/AFR log)
- **AFR log (รถเบนซิน)** — DATA → **AFR log**: ตาราง AFR เฉลี่ย แกนนอน = รอบเครื่อง (ทีละ 1,000 รอบ, 0K–7K) แกนตั้ง = คันเร่ง TPS (0 / 5 / 10 / 20 / 35 / 50 / 75 %); ช่องปัจจุบันมีกรอบเขียว, ช่องที่ AFR 13.8–15.2 สีเขียว; ปุ่ม **Reset** ล้างตาราง
- **CRP log (รถดีเซล)** — DATA → **CRP log**: ตารางแรงดัน CRP (โวลต์ตามเส้นที่ตั้งไว้ใน SETUP 2 → CRP sensor) ต่อช่วงรอบ ค่าเฉลี่ย / ต่ำสุด / สูงสุด + จำนวนตัวอย่าง; มุมขวาบอก เบนซิน / ดีเซล / ไฮบริด ตามที่อ่านจาก ECU
  - เกจบันทึกลงตารางทั้งสองตลอดเวลาที่ขับ (10 ครั้ง/วินาที ตอนรอบ ≥ 400) ไม่ต้องเปิดหน้านั้นค้างไว้ — **ตารางอยู่ในหน่วยความจำ หายเมื่อปิดเครื่อง/เปลี่ยนรุ่นรถ** จึงออกแบบให้ดึงเข้าแอปผ่าน LOG_GET (ด้านล่าง) เก็บไว้
  - AFR ต้องให้ ECU ตอบ PID 24 หรือ 44 (เซนเซอร์ออกซิเจนแบบ wideband / lambda) ถ้ารถไม่ตอบ ตารางจะว่าง; CRP ต้องมี PID 23 หรือ 59 (รถดีเซล/ฉีดตรง)
- **ซิงค์กับ Jet Honda APP ผ่าน USB (MFB-LINK) ทำงานทั้งสองโหมด** — ใช้สาย USB เดิมของ CYD (115200 baud, ช่องเดียวกับที่แฟลช; ถ้าใช้ Android ต้องมีสาย OTG):
  - **SENSORS (0x20) ตอบจริงแล้ว** (v1.0.14 ปฏิเสธ): AFR, อุณหภูมิน้ำมันเครื่อง, แรงดัน O2, แรงดัน CRP ตามที่เกจอ่านได้ — ธง "valid" ในไบต์ flags บอกว่าค่าไหนมี (ไม่มี GPS ไม่มีเกียร์: ธงเป็น 0 แอปจะใช้ GPS มือถือต่อ)
  - **LIVE (0x21) ใหม่**: ค่าสดทั้งหมด 48 ไบต์ — รอบ, ความเร็ว, คันเร่ง, MAP, น้ำ, อากาศเข้า, แบต, timing, หัวฉีด (K-line), AFR, lambda, CRP (MPa/โวลต์), บูสต์, อัตราสิ้นเปลือง, น้ำมันเครื่อง, โหลด, ระยะทาง/เวลาทริป + ธงบอกโหมด/ลิงก์/ดีเซล/ไฮบริด/MIL
  - **LOG_GET (0x22) ใหม่**: ดึงตาราง log — ชนิด 0 = AFR ต่อช่วงรอบ, 1 = CRP โวลต์ต่อช่วงรอบ, 2 = แผนที่ AFR (คันเร่ง × รอบ) พร้อมจำนวนตัวอย่างของแต่ละช่อง (แอปเอาไปรวมกับ AFR log/FIT ของตัวเองได้)
  - **คำสั่งเหล่านี้ไม่ล็อกสาย K-line**: แอปถามค่าถี่ ๆ ได้โดยเกจยังอ่าน ECU ต่อ (เกจถอยออกจากสาย K เฉพาะตอนแอปส่ง PING/WAKE/SENSE/TXRX เหมือน v1.0.14)
  - **บนจอเกจ**: ขณะแอปคุยอยู่ (ภายใน 8 วินาทีหลังคำสั่งล่าสุด) แถบบนขวาขึ้น `APP …`; ในโหมด K-line หน้า K-line ขึ้น "Jet Honda APP is using the K-line" ตอนแอปใช้สาย
  - ในโหมดรถ: คำสั่งสาย K (WAKE/TXRX/SENSE) ยังใช้ได้ถ้าต่อบอร์ด K-line ไว้ แต่ค่าที่แอปอ่านผ่านสายจะไม่ถูกนำมาแสดงบนเกจ (เกจแสดงค่าจาก ELM327 ของมันเอง)
  - 📌 **ฝั่งแอป**: แอป Jet_HONDA_APP ตัวปัจจุบันเรียก SENSORS อยู่แล้ว (ค่า AFR / น้ำมัน / O2 / CRP จะโผล่ในแผงเซนเซอร์ของแอปเอง) ส่วน **LIVE และ LOG_GET เป็นคำสั่งใหม่ ต้องเพิ่มโค้ดฝั่งแอปเพื่อเรียกและแสดง** — ยังไม่ได้แก้โปรเจกต์แอปให้ (ตัวถอดรหัสพร้อมใช้อยู่ในหัวข้อ "รูปแบบข้อมูลซิงค์" ด้านล่าง)
- **สีสัน (COLOURFUL) ย้ายมาเป็นปุ่มใน SETUP → MORE (แถวปุ่มล่าง)**: ปุ่ม "Colourful" เปิด/ปิด (เปิดเป็นค่าเริ่มต้น) ใช้ได้ทั้งสองโหมด — โหมดรถมี 4 ปุ่มในแถวนั้น (Test alert / Reset peak / CRP sensor / Colourful), โหมด K-line มี 3 ปุ่ม (ไม่มี CRP sensor) และแถว PROTOCOL โชว์ "HONDA K-LINE" แทน (ไม่มีโปรโตคอล ELM327 ให้เลือก)
- **คงจาก v1.0.14**: หน้าจอ Honda (เฉพาะโหมด K-line), สีสันทั้งระบบ (วงรอบไล่เขียว→แดง, ค่าแต่ละตัวมีสี), การอ่านค่าหัวฉีด (INJ) ใน K-line

### รูปแบบข้อมูลซิงค์ (MFB-LINK ใหม่ใน v1.0.15 — เฟรมและ LIVE / LOG_GET)
เฟรม: `55 AA | type | lenL lenH | payload | xor(type, lenL, lenH, payload)` ตอบกลับ type|0x80, ไบต์แรกของ payload = สถานะ (0 ok, 1 ECU ไม่ตอบ, 2 ปฏิเสธ) ทุกฟิลด์ little-endian — **ตำแหน่งด้านล่างนับหลังไบต์สถานะ** (เหมือน `r.slice(1)` ในแอป)

| คำสั่ง | type | ส่งไป | ตอบ (หลังสถานะ) |
|---|---|---|---|
| SENSORS | 0x20 | ไม่มี payload | 21 ไบต์ ตามเดิมของแอป: `afr u16 ×100 · gpsKmh u16 ×10 · sats · satsView · lat i32 · lon i32 · eot+40 u8 · o2 u8 ×100 · rsv · flags · crpV u16 ×1000 · gear` — เกจเติม AFR, eot, o2, crpV (flags bit0 AFR, bit2 EOT, bit3 O2, bit4 CRP); GPS/เกียร์เป็น 0 และธงปิด |
| LIVE | 0x21 | ไม่มี payload | 48 ไบต์ (ตารางล่าง) |
| LOG_GET | 0x22 | 1 ไบต์ ชนิด: 0, 1 หรือ 2 | ชนิด 0/1: 4 + 8×8 = 68 ไบต์ · ชนิด 2: 4 + 7 + 56×4 = 235 ไบต์ · ชนิดอื่น/ไม่ใส่ → สถานะ 2 |

LIVE (ออฟเซ็ต:ชนิด): `0:u8 เวอร์ชัน=1 · 1:u8 โหมด (0 รถ, 1 K-line) · 2:u8 สถานะ (bit0 ลิงก์กับ ECU, bit1 demo, bit2 ดีเซล, bit3 ไฮบริด, bit4 มอเตอร์ไซค์, bit5 MIL) · 3:u8 สำรอง · 4:u16 ธงค่าที่ valid (bit0 รอบ, 1 ความเร็ว, 2 คันเร่ง, 3 MAP, 4 น้ำ, 5 อากาศเข้า, 6 แบต, 7 timing, 8 หัวฉีด, 9 AFR, 10 lambda, 11 CRP, 12 บูสต์, 13 อัตราสิ้นเปลือง, 14 น้ำมันเครื่อง, 15 โหลด) · 6:u16 รอบ · 8:u16 ความเร็ว×10 km/h · 10:u16 คันเร่ง×10 % · 12:u16 MAP×10 kPa · 14:i16 น้ำ×10 °C · 16:i16 อากาศเข้า×10 °C · 18:u16 แบต×100 V · 20:i16 timing×10 ° · 22:u16 หัวฉีด×100 ms · 24:u16 AFR×100 · 26:u16 lambda×1000 · 28:u16 CRP×10 MPa · 30:u16 CRP×1000 V · 32:i16 บูสต์×10 kPa · 34:u16 อัตราสิ้นเปลือง×100 L/h · 36:i16 น้ำมันเครื่อง×10 °C · 38:u16 โหลด×10 % · 40:u32 ระยะทริป เมตร · 44:u32 เวลาทริป วินาที`

LOG_GET: `0:u8 ชนิด · 1:u8 จำนวนแถว · 2:u8 จำนวนคอลัมน์ (8) · 3:u8 รอบต่อคอลัมน์ ÷100 (10 = 1,000 รอบ รถยนต์ / 20 = 2,000 รอบ มอเตอร์ไซค์)` แล้วต่อด้วย — ชนิด 0/1: 8 คอลัมน์ × `{จำนวนตัวอย่าง u16 · เฉลี่ย u16 ×100 · ต่ำสุด u16 ×100 · สูงสุด u16 ×100}` (คอลัมน์ c = รอบ c×ขั้น ถึง (c+1)×ขั้น, คอลัมน์สุดท้ายไม่จำกัดบน) · ชนิด 2: ค่าคันเร่ง % ของแต่ละแถว 7 ไบต์ (0 5 10 20 35 50 75) แล้ว 7 แถว × 8 คอลัมน์ × `{จำนวนตัวอย่าง u16 · AFR เฉลี่ย u16 ×100}` — จำนวนตัวอย่าง 0 = ช่องว่าง (ค่าอื่นเป็น 0); จำนวนตัวอย่างนับ 10 ครั้ง/วินาที ตัดที่ 65,535

ตัวถอดรหัสฝั่งแอป (JavaScript — ทดสอบกับไบต์จริงจากเฟิร์มแวร์แล้ว; `p` = ข้อมูลหลังไบต์สถานะ, เรียกผ่าน `link.request(0x21, [], 700)` / `link.request(0x22, [ชนิด], 900)` แล้ว `.slice(1)`):
```js
const u16 = (p, i) => p[i] | (p[i + 1] << 8), s16 = (p, i) => (u16(p, i) << 16) >> 16, u32 = (p, i) => (p[i] | (p[i + 1] << 8) | (p[i + 2] << 16) | (p[i + 3] << 24)) >>> 0;
function decodeLive(p) {
  if (!p || p.length < 48 || p[0] !== 1) return null;
  const f = u16(p, 4), v = (b, x) => ((f >> b) & 1 ? x : null);               // null = ค่านั้นยังไม่มี
  return { mode: p[1] ? 'kline' : 'car', linked: !!(p[2] & 1), demo: !!(p[2] & 2), diesel: !!(p[2] & 4), hybrid: !!(p[2] & 8), bike: !!(p[2] & 16), mil: !!(p[2] & 32),
    rpm: v(0, u16(p, 6)), speed: v(1, u16(p, 8) / 10), tps: v(2, u16(p, 10) / 10), map: v(3, u16(p, 12) / 10), ect: v(4, s16(p, 14) / 10), iat: v(5, s16(p, 16) / 10),
    batt: v(6, u16(p, 18) / 100), timing: v(7, s16(p, 20) / 10), inj: v(8, u16(p, 22) / 100), afr: v(9, u16(p, 24) / 100), lambda: v(10, u16(p, 26) / 1000),
    crpMPa: v(11, u16(p, 28) / 10), crpV: v(11, u16(p, 30) / 1000), boost: v(12, s16(p, 32) / 10), fuelLh: v(13, u16(p, 34) / 100), oil: v(14, s16(p, 36) / 10), load: v(15, u16(p, 38) / 10),
    tripKm: u32(p, 40) / 1000, tripSec: u32(p, 44) };
}
function decodeLog(p) {                                      // ชนิด 0 = AFR ต่อช่วงรอบ, 1 = CRP โวลต์ต่อช่วงรอบ, 2 = แผนที่ AFR
  if (!p || p.length < 4 || p[0] > 2) return null;
  const kind = p[0], rows = p[1], cols = p[2], rpmStep = p[3] * 100; let o = 4;
  if (kind === 2) {
    const tps = Array.from(p.slice(o, o + rows)); o += rows; const cells = [];
    for (let r = 0; r < rows; r++) { const row = []; for (let c = 0; c < cols; c++, o += 4) { const n = u16(p, o); row.push({ n, avg: n ? u16(p, o + 2) / 100 : null }); } cells.push(row); }
    return { kind, tps, rpmStep, cells };                    // cells[แถวคันเร่ง][คอลัมน์รอบ]
  }
  const bands = [];
  for (let c = 0; c < cols; c++, o += 8) { const n = u16(p, o); bands.push({ n, avg: n ? u16(p, o + 2) / 100 : null, min: n ? u16(p, o + 4) / 100 : null, max: n ? u16(p, o + 6) / 100 : null }); }
  return { kind, rpmStep, bands };
}
```

## ของใหม่ใน v1.0.14 (Honda K-line อย่างเดียว + ต่อ Jet Honda APP ผ่าน USB + สีสันมากขึ้น)
> หมายเหตุ: v1.0.15 เอาโหมดรถยนต์/Bluetooth/ELM327/CAN listen/PROTOCOL/CRP sensor กลับมา และ SENSORS ตอบจริงแล้ว — ข้อ "เอาออก" และ "ปฏิเสธ SENSORS" ด้านล่างจึงไม่เป็นจริงอีกต่อไป ส่วน MFB-LINK / สีสัน / หน้าจอ Honda ของ v1.0.14 ยังอยู่ (หน้าจอ Honda ใช้เฉพาะโหมด K-line)
- **เอา Bluetooth / ELM327 / CAN ออกหมด เหลือ Wi-Fi เฉพาะตัวอัปเดต**: เกจเหลือโหมด Honda K-line โหมดเดียว (บอร์ด K-line ที่ IO22/IO27 ตามตารางต่อสายของ v1.0.13 ด้านล่าง); ตัวเกจปกติไม่มี Wi-Fi/บลูทูธ แล้ว Wi-Fi อยู่เฉพาะในโหมดอัปเดต (SETUP → UPDATE → รีสตาร์ทเข้าตัวอัปเดต) ซึ่งทำงานเหมือนเดิม
  - **เอาออก**: หน้า BT device และปุ่มสลับโหมด, ปุ่ม CAN listen (หน้า ECU), แถว PROTOCOL (SETUP 2), ปุ่ม CRP sensor (SETUP 2), ปุ่ม CRP log / AFR log (หน้า DATA) — หน้าเก่าบางหน้ายังเหลือในโค้ดแต่ไม่มีปุ่มเข้าแล้ว
  - ปุ่มซ้ายสุดของ SETUP เปลี่ยนจาก Bluetooth เป็น **K-LINE** (เปิดหน้า K-line); ค่าเริ่มต้นเป็นมอเตอร์ไซค์ (ถัง 6 L, รอบเตือน 8,500) ตั้งแต่เปิดเครื่องครั้งแรก
  - ใครยังต้องใช้เกจกับ ELM327/รถยนต์ ให้ใช้ v1.0.13 หรือเก่ากว่า (ยังโหลดได้จากหน้า Releases)
- **ต่อกับ Jet Honda APP ผ่านสาย USB — เกจเป็นตัวต่อปลั๊ก OBD2 K-line ให้แอป**:
  - ต่อสาย USB ของ CYD (พอร์ตเดียวกับที่แฟลช) เข้าเครื่องที่เปิดแอป (คอมหรือ Android ที่ Chrome/Edge รองรับ Web Serial / USB-OTG) → ในแอปเลือกช่องทาง **Smart Gauge (BLE / USB)** แล้วต่อแบบ USB — แอปคุยกับเกจด้วยโปรโตคอล MFB-LINK ที่ 115200 baud (ตรงตามที่เขียนไว้ใน README ของแอป)
  - เกจรับคำสั่ง **PING / WAKE / TXRX / SENSE**: เกจเป็นคนปลุก ECU (K ต่ำ 70 ms แล้วสูง 130 ms), ส่งเฟรม Honda ที่แอปสั่ง และส่งเฟรมที่ ECU ตอบกลับให้แอป (ตัดเสียงสะท้อน/echo ออกให้เอง) — ชื่อที่ตอบ PING: `JET SMART GAUGE K-LINE v1.0.14`
  - **ปฏิเสธ** คำสั่ง SENSORS และ FILE_* (ส่งไฟล์มาเก็บบนเกจ/ปุ่ม FLASH ในแอป): เกจไม่มีที่เก็บไฟล์ (แฟลช 4 MB ถูกแบ่งให้ตัวเกจ + ตัวอัปเดต ไม่มีพาร์ทิชันระบบไฟล์) และ **ไม่รองรับ BLE** (แอปต้องต่อผ่าน USB) — ถ้าอยากได้ BLE บอกได้
  - **ระหว่างแอปใช้สาย** เกจถอยออกจากสาย K-line ให้: หยุดอ่านเองจนแอปเงียบไป 8 วินาที (นานเป็น 60 วินาทีหลังแอปส่งเฟรมแบบเขียน/แฟลช เพื่อไม่ให้เกจแทรกกลางงาน) แล้วกลับมาอ่านค่าเองอัตโนมัติ; หน้า K-line ขึ้น "Jet Honda APP is using the K-line" และตารางสด 11 ที่แอปอ่านผ่านเกจก็ถูกเอามาแสดงบนหน้าจอเกจด้วย
  - ⚠️ **การเขียน/แฟลช ECU ผ่านเกจยังไม่เคยทดสอบ** และเสี่ยง (ไฟตก/สายหลุดกลางทางทำให้ ECU เสียได้) — ลองแค่ "อ่าน/ดูด" ก่อน อย่าเขียน ECU จนกว่าจะลองกับกล่องสำรองได้
- **สีสันมากขึ้น (SETUP → MORE → COLOURFUL เปิด/ปิด; เปิดเป็นค่าเริ่มต้น)**: ค่าแต่ละตัวมีสีของตัวเอง (น้ำหล่อเย็นฟ้าน้ำแข็ง, อากาศเข้ามิ้นต์, แบตเหลือง, คันเร่งเขียว, MAP ม่วง, Timing ชมพู, หัวฉีดเขียวมะนาว ฯลฯ) ถ้าค่าสูง/ต่ำผิดปกติยังเป็นสีเตือน (ส้ม/แดง) เหมือนเดิม; **วงรอบไล่สีเขียว → เหลือง → ส้ม → แดง** ตามรอบ (แดงเต็มที่รอบเตือนที่ตั้งไว้) แถบไฟเตือนรอบด้านบนไล่สีเดียวกัน และกราฟแต่ละเส้นมีสีของตัวเอง; ปิดแล้วกลับเป็นหน้าตาขาว/น้ำเงิน-แดงของ v1.0.13
- **หน้าจอปรับให้เป็นของมอเตอร์ไซค์ Honda**:
  - หน้าหลัก: แตะกลางวงหรือแถบล่างสลับ **ความเร็ว ↔ ระยะทริป (km)** (เดิมสลับ CRP/AFR); ช่องค่า 6 ช่องเริ่มต้น: COOLANT, THROTTLE, TIMING, INTAKE, BATTERY, MAP
  - DATA 16 ช่อง (ชุด Honda): รอบ, ความเร็ว, คันเร่ง, MAP, น้ำหล่อเย็น, อากาศเข้า, แบต, Timing, **หัวฉีด (ms — ใหม่ จากตาราง 11 ไบต์ 14–15 ÷ 250)**, ระยะทริป, ความเร็วเฉลี่ย, เวลาขับ, รอบสูงสุด, ความเร็วสูงสุด, น้ำหล่อเย็นสูงสุด, แบตต่ำสุด (ของทริปนี้); ปุ่มในหน้า DATA เหลือ MAIN / ALL PIDS
- **ยังไม่มี**: อ่าน/ลบรหัสข้อขัดข้อง (DTC) ของ Honda ผ่านเกจ (หน้า CODES/มอนิเตอร์/Freeze ขึ้นว่าลิงก์นี้อ่านไม่ได้); น้ำมันในหน้า TRIP เป็นค่าประมาณจาก MAP/รอบ/ขนาดเครื่อง ไม่ใช่ค่าจาก ECU
- **ทดสอบแล้วบนคอมพิวเตอร์ (ไม่ใช่บอร์ดจริง)**: ECU Honda จำลอง + แอปจำลอง — ต่อติดทั้งบอร์ดที่มี/ไม่มี echo, ตารางสั้น/ผิดรูป, กุญแจ OFF/ON, ECU หลับ/ตื่น, checksum ผิด, ECU ตอบช้า, เฟรมแอปแบบมีสัญญาณรบกวน/ถูกตัดครึ่ง/ผิด xor, เฟรม 134 ไบต์, เกจไม่แย่งสายตอนแอปใช้และกลับมาเองหลัง 8 วินาที (60 วินาทีหลังเฟรมเขียน), หน้าจอวาดถูกตอนแอปใช้สาย; พรีวิวเว็บ 206 เช็ก + แกลเลอรี 55 หน้า (รถยนต์ + Honda K-line); คอมไพล์ตรวจไวยากรณ์ทั้งตัวเกจและตัวอัปเดต; บิลด์จริงบน PlatformIO ผ่านที่ GitHub Actions (ขนาดไฟล์ตามด้านบน)
- เครื่องที่ลง v1.0.x อัปเดตผ่าน Wi-Fi ได้เลย (SETUP → UPDATE) — ตารางพาร์ทิชันเหมือนเดิม ไม่ต้องแฟลชสาย; ตัวอัปเดต (ส่วนที่ 2 ของแฟลช) ไม่ถูกเปลี่ยนด้วยวิธีนี้ จึงยังเป็นรุ่นที่แฟลชไว้ตอนแรก และใช้ได้ตามปกติ
- ⚠️ **ไม่ได้ทดสอบกับบอร์ด CYD, มอเตอร์ไซค์ และแอป Jet Honda APP ตัวจริง** ตำแหน่งไบต์ของตาราง 11 ยังไม่ยืนยันกับรุ่นของคุณ ถ้าเจอปัญหาส่งหน้า K-line (ตารางดิบ) มาให้ดูได้

## ของใหม่ใน v1.0.13 (รองรับ K-line ผ่านบอร์ด K-line — ต่อปลั๊ก 6 พิน Honda)
> หมายเหตุ: ปุ่มสลับโหมด Bluetooth ↔ K-line ที่พูดถึงด้านล่างถูกเอาออกใน v1.0.14 — เกจเป็น K-line อย่างเดียว เข้าหน้า K-line ที่ **SETUP → K-LINE**; ส่วนวิธีต่อสายและโปรโตคอลยังใช้ตามนี้
- **โหมดใหม่ "Honda K-line"**: เกจคุยกับ ECU มอเตอร์ไซค์ Honda ผ่านสาย K-line ตรง ๆ จากบอร์ด K-line (**ไม่ใช้ ELM327 / บลูทูธ**) — ELM327 คุยโปรโตคอลของ Honda ไม่ได้ จึงต้องใช้บอร์ดนี้
  - **สลับโหมด**: SETUP → ปุ่ม **Bluetooth** (หน้า BT device) → ปุ่ม **Honda K-line** (ข้างกล่องอะแดปเตอร์) → เข้าหน้า K-line; อยากกลับใช้บลูทูธ กดปุ่ม **Bluetooth** มุมขวาบนของหน้า K-line เครื่องจำโหมดไว้หลังปิดเครื่อง
  - **โปรโตคอล** (ตามแอป Jet_HONDA_APP ของคุณ): 10400 baud 8N1 สายเดียว → ปลุก ECU (K ต่ำ 70 ms แล้วสูง 130 ms) → ping `FE 04 72 8C` → อ่านรหัส ECU (ตาราง `00`) → อ่าน **ตารางสด `11`** วนต่อเนื่อง (การถามต่อเนื่องเป็น keep-alive ในตัว ไม่ให้ ECU หลับ) → ถอดรหัสเป็น RPM, ความเร็ว, ECT, IAT, MAP, TPS, แบตเตอรี่, มุมจุดระเบิด (หัวฉีด ms แสดงในหน้า K-line)
  - **ค่าที่เข้าเกจ**: รอบ, ความเร็ว, น้ำหล่อเย็น, อากาศเข้า, MAP, คันเร่ง (TPS %), แรงดันแบต, Timing — ใช้ได้ทุกหน้าเดิม (หน้าหลัก, Data, กราฟ, Trip, Peaks, เตือน) ค่าที่ตารางนี้ไม่มี (น้ำมันเครื่อง, load, AFR ฯลฯ) ขึ้น "--"; อัตราสิ้นเปลืองประมาณจาก MAP + IAT + รอบ + ความจุเครื่อง (เลือกรุ่นที่ SETUP → VEHICLE ให้ตรง)
  - **ช่องหน้าหลักเริ่มต้นของ K-line**: COOLANT, THROTTLE, TIMING, INTAKE, BATTERY, MAP (ปรับเองได้เหมือนเดิม); ครั้งแรกที่สลับเป็น K-line ถ้ายังไม่ได้เลือกรุ่น เกจตั้งค่าแบบมอเตอร์ไซค์ให้ (ถัง 6 L, ไฟ shift 8,500) ชื่อบนแถบเป็น "HONDA BIKE"
  - **หน้า K-line**: ตารางดิบ (hex) + จำนวนครั้ง/วินาที, ค่าที่ถอดรหัสแล้ว, รหัส ECU, สถานะ ("รอ ECU" / "ECU ตอบแล้ว" / "ไม่ตอบ: ตรวจสาย K, +12V, GND")
  - **ลิงก์นี้ยังไม่มี**: อ่าน/ลบรหัสข้อขัดข้อง, freeze frame, มอนิเตอร์ (หน้าเหล่านั้นขึ้นว่าอ่านไม่ได้), CAN listen (ขึ้น "CAN only"); รุ่นที่ใช้ CAN บนปลั๊ก 6 พิน (ขา B/E) ไม่รองรับ
- **วิธีต่อสาย (ปลั๊ก DLC 6 พิน ตามคู่มือ Honda)** — ใช้ 3 ขา:

  | ปลั๊ก 6 พิน Honda | ปลั๊ก OBD-II 16 พิน (สายแปลง) | ต่อไปที่ |
  |---|---|---|
  | **D** = K-line | ขา 7 | ขา **K** ของบอร์ด K-line |
  | **F** = VBAT (+12 V) | ขา 16 | ขา **VBAT/+12V** ของบอร์ด (ใส่ฟิวส์ 1 A ในสายนี้) |
  | **A** = GND | ขา 5 | **GND** ของบอร์ด และ GND ของ CYD |
  | B (CAN_H), C (SCS), E (CAN_L) | — | ไม่ต่อ |

  | บอร์ด K-line | ESP32 CYD |
  |---|---|
  | VCC (5 V) | 5 V / VIN (ขั้ว P1) |
  | GND | GND |
  | ขารับสัญญาณเข้า **RX / RXD** (บอร์ดรับจากเกจ) | **IO27** (ขั้ว CN1) |
  | ขาส่งสัญญาณออก **TX / TXD** (บอร์ดส่งให้เกจ) | **IO22** (ขั้ว CN1) **ผ่านตัวแบ่งแรงดัน** — ขา TX ของบอร์ดออก 5 V แต่ขา ESP32 ทนได้ 3.3 V: ต่อตัวต้านทาน 2.2 kΩ อนุกรมเข้า IO22 และ 3.3 kΩ จาก IO22 ลง GND (≈ 3.0 V) |

  - ใช้บอร์ดที่มีทรานซีฟเวอร์ K-line (L9637D / MC33290 / SI9243 หรือแบบออปโต) และต้อง **ไม่กลับสัญญาณ** (idle = สูง); **ห้ามต่อสาย K (12 V) เข้าขา ESP32 ตรง ๆ**
  - เกจรู้เองว่าบอร์ดสะท้อนไบต์ที่ส่ง (echo) หรือไม่ ไม่ต้องตั้งค่า; อยากเปลี่ยนขา ให้เพิ่ม `-DKL_RX=<ขา> -DKL_TX=<ขา>` ใน `build_flags` ของ `platformio.ini` (IO21 ใช้กับแบ็คไลท์, IO35 รับอย่างเดียว)
  - ขาบน CYD ตามป้ายบน PCB (CN1 มี GND, IO22, IO27, 3V3) — เช็กกับบอร์ดของคุณก่อนต่อ
- **วิธีทดสอบกับรถ**: ต่อสายตามตาราง → เปิดกุญแจ ON (ยังไม่ต้องสตาร์ทก็ได้) → SETUP → Bluetooth → **Honda K-line** → ดูหน้า K-line: ต้องขึ้น "ECU answering" และมีตัวเลข "xx/s" ที่ตารางสด; ติดเครื่องแล้วรอบ/ความเร็ว/อุณหภูมิต้องสมเหตุสมผล → ถ่ายภาพหน้านี้ (แสดง hex ของตาราง) ส่งมา
  - ถ้าขึ้น "No answer": เช็ก 1) ไฟ +12 V ที่บอร์ด (ขา F ของปลั๊กมีไฟตอนกุญแจ ON เท่านั้นในบางรุ่น) 2) สาย K ไปขา D 3) GND ร่วม 4) สลับสาย RX/TX
  - ถ้าติดแต่ค่าไม่ตรง (เช่น รอบแปลก ๆ): ตำแหน่งไบต์ของตาราง 11 มาจากชุมชนและยังไม่ยืนยันทุกรุ่น (Wave / Click / PCX / ADV ฯลฯ) — ส่งภาพหน้า K-line มา จะปรับตำแหน่งให้ตรงรุ่น
- **ทดสอบแล้วใน ECU Honda จำลอง** (UART ปลอม): ติดภายใน ~0.3 วินาที, ~26 ตาราง/วินาที, ใช้ได้ทั้งบอร์ดที่มี/ไม่มี echo, ECU หลับแล้วปลุกใหม่เอง, เช็กซัมเสีย 20% ยังคงลิงก์, ECU ตอบช้า 80 ms ยังใช้ได้ (10/วินาที), ตาราง 0 หายไปยังติด, ไม่มีตารางสด/ตอบช้าเกิน ไม่ติดและบอกสถานะ; โหมดบลูทูธเดิมทำงานเหมือน v1.0.12 ทุกตัวเลข
- เครื่องที่ลง v1.0.0–v1.0.12 อัปเดตผ่าน Wi-Fi ได้เลย (SETUP → UPDATE); ต้องมีบอร์ด K-line ต่อสายเองจึงใช้โหมดใหม่ได้
- ⚠️ **ไม่ได้ทดสอบกับมอเตอร์ไซค์และบอร์ดจริง** ทุกอย่างมาจากตัวจำลองบนคอมพิวเตอร์ (ECU จำลองสร้างตามโปรโตคอลในแอป Jet_HONDA_APP) — เวลาตอบจริง ค่าตาราง และรุ่นที่รองรับต้องยืนยันกับรถจริง

## ของใหม่ใน v1.0.12 (ค่าที่ขยับเร็วรีเฟรชไวขึ้น + จูนจังหวะ ELM + หน้าฟังบัส CAN)
- **ถามค่าตามตารางเวลาต่อ PID** (แนวเดียวกับ AndrOBD): ค่าที่ขยับเร็ว (LOAD, MAP/บูสต์, MAF, throttle, แป้นคันเร่ง, lambda/AFR, แรงดันราง, แรงบิด, ไทมิ่ง) ถูกถามทุกรอบเหมือนเดิม ส่วนค่าที่เปลี่ยนช้า (น้ำ/น้ำมันเครื่อง 1 วิ, แบต/ไอดี 0.6 วิ, ระดับน้ำมัน/บารอมิเตอร์/อุณหภูมิแวดล้อม 2.5 วิ) รอตามเวลา ไม่แย่งที่ในคำขอ → ค่าที่ขยับเร็วได้ที่เพิ่ม
  - ตัวจำลอง CAN (หน้าหลัก THR/PEDAL/LOAD/COOL/MAP/INTAKE): THR, LOAD, MAP รีเฟรช **304 → 170 ms** (เร็วขึ้น ~1.8 เท่า); หน้า Data 16 ช่อง **474 → 242 ms** (~2 เท่า); น้ำ/ไอดี/แบต ช้าลงตามที่ตั้งใจ (น้ำ ~1.2 วิ) เพราะค่าเหล่านี้ไม่ได้ขยับเร็ว
  - รอบ/ความเร็ว/แป้นคันเร่งยังเท่าเดิม (68 ms ในตัวจำลอง); K-line และโหมดถามทีละค่าไม่เปลี่ยน; อ่านครบทั้ง 55 PID ที่ทดสอบ (ไม่มีค่าไหนถูกข้าม)
- **CAN: ตั้ง ATAT2 + ATST19** (adaptive timing 2, รอคำตอบ 100 ms แทน 200 ms) หลังได้ค่าชุดแรกแล้ว — ช่วยอะแดปเตอร์ที่ไม่รับตัวเลข "จำนวนคำตอบ" (รอบเครื่องจาก ~111 → ~83 ms ในตัวจำลองที่สมมติว่าอะแดปเตอร์รอสั้นลง 25 ms — ยังไม่ได้วัดกับอุปกรณ์จริง)
  - **ถอยกลับเองอัตโนมัติ**: อะแดปเตอร์ที่ไม่รับ ATAT2 จะไม่ถูกแตะ; ถ้าใน 100 คำขอแรกรอบ/ความเร็วหายเกิน 1 ใน 3 จะส่ง ATAT1 + ATST32 (ค่าเดิมของ ELM) คืนทันที และจำว่าอะแดปเตอร์ตัวนี้ไม่เหมาะ ไม่ลองซ้ำ (ถ้ารถเงียบทั้งที่ค่าเดิม = ดับเครื่อง ไม่โทษอะแดปเตอร์ ไม่จำ)
  - K-line ไม่ถูกแตะ (ยัง ATST64 เหมือนเดิม)
- **หน้าใหม่ ECU → ปุ่ม CAN listen** (รถ CAN 11 บิต): สั่ง `ATH1` + `ATCRA 202` + `ATMA` ฟังเฟรมที่รถ "ประกาศเอง" บนพอร์ต OBD โดยไม่ต้องถาม ดูอัตราเฟรม/วินาที และไบต์ดิบ
  - ปุ่ม **ID 202**: ฟังเฉพาะ ID 202 (เฟรมข้อมูลเครื่องยนต์ของ Mazda 3 ปี 2017: ไบต์ 0–1 = รอบ ÷4, ไบต์ 2–3 = ความเร็ว ÷100, ไบต์ 4 = คันเร่ง) แสดงไบต์ดิบ + ค่าที่ถอดตามแบบนั้น — **ของ Mazda 2 ยังไม่ยืนยันว่าเหมือนกัน** ให้เทียบตัวเลขกับหน้าปัดรถ
  - ปุ่ม **All IDs**: ฟังทุก ID แสดง 5 ID ที่ถี่สุด + จำนวน ID ที่เห็น (อะแดปเตอร์อาจขึ้น "Adapter buffer full" ซึ่งปกติเมื่อฟังทุก ID)
  - ออกจากหน้านี้ เกจคืนค่า ATAR/ATH0 แล้วกลับไปอ่านค่าปกติเอง; ระหว่างเปิดหน้านี้เกจหยุดถามค่าปกติ (ค่าบนจอค้างแล้วขึ้น -- ภายใน 3–8 วิ)
  - **วิธีทดสอบ**: ต่ออะแดปเตอร์ ติดเครื่อง → ECU → CAN listen → ดู "Frames per second" ทั้งสองโหมดอย่างน้อย 5 วิ แล้วถ่ายภาพหน้าจอส่งมา: ถ้าขึ้นเลขหลักสิบ–ร้อย/วินาที = รถส่งข้อมูลเองได้ (ทำโหมดอ่านเร็วต่อได้); ถ้า 0 / "No frames" = ตัวรถหรืออะแดปเตอร์ไม่ให้ฟัง (ไม่ต้องทำต่อ ไม่เสียอะไร)
- เครื่องที่ลง v1.0.0–v1.0.11 อัปเดตผ่าน Wi-Fi ได้เลย (SETUP → UPDATE)
- ⚠️ **ไม่ได้ทดสอบกับรถและบอร์ดจริง** ตัวเลขทั้งหมดมาจากตัวจำลองบนคอมพิวเตอร์ (อะแดปเตอร์จำลอง) — ATMA บนอะแดปเตอร์โคลนอาจไม่เสถียร, และยังไม่ได้ทำ "โหมดอ่านจากเฟรมที่รถส่งเอง" เพราะต้องรอผลจากหน้า CAN listen ก่อน

## ของใหม่ใน v1.0.11 (เข็มรอบและค่าคันเร่งตามเท้าไวขึ้น)
- **เข็มรอบ ตัวเลขรอบ และแถบไฟเตือนรอบ วิ่งนำตามแนวโน้มตอนเร่ง/ถอนคันเร่งแรง**: รถตอบค่ารอบทุก ~70 ms (CAN) และภาพต้องใช้อีก ~50 ms กว่าจะขึ้นจอ เกจจึงต่อแนวโน้มล่าสุดไปอีกช่วงสั้น ๆ (ไม่เกิน 350 รอบ) ให้เข็มอยู่ใกล้รอบจริงของเครื่องตอนนี้ ไม่ใช่รอบเมื่อครู่ที่แล้ว
  - **ตอนเดินเบา/ครูซ ตัวเลขเป็นค่าที่ ECU ส่งมาเป๊ะ ๆ เหมือนเดิม** (แนวโน้มที่เล็กกว่า ~600 รอบ/วินาที ถือเป็นสัญญาณรบกวน ไม่นำมาต่อ และต้องเป็นทิศเดียวกัน 2 ครั้งติดกันถึงจะนำ)
  - ตัวจำลอง (เร่งเต็ม ~2,900 รอบ/วินาที, ECU ตอบทุก 70 ms): ความคลาดเฉลี่ยของรอบที่แสดงเทียบรอบจริง **290 → ~95 รอบ**; ถอนคันเร่งจาก 4,000 รอบ 336 → 131; blip สั้น ๆ 350 → 240; เดินเบา ±15 รอบ 12 → 12 (ไม่สั่นเพิ่ม); K-line ได้ผลน้อยกว่า (KWP 571 → 410, ISO 9141 932 → 866 เพราะรถตอบห่าง)
  - ⚠️ ตรงจุดกลับทิศ (เหยียบแล้วยกทันที) เข็มอาจเลยไปได้ชั่วครู่ ไม่เกิน ~350 รอบจากค่าล่าสุดที่รถส่งมา (ในตัวจำลองจุดแย่สุดตอน blip 600 → 665 รอบ) ไฟเตือนรอบจึงติดไวขึ้นเล็กน้อยตอนเร่งแรง ส่วน **การแจ้งเตือน (ความร้อน/แบตเตอรี่ ฯลฯ) ใช้ค่าจริง ไม่ใช้ค่านำ**
- **ค่าแป้นคันเร่ง (PID 49) หรือ throttle (PID 11) ที่อยู่บนจอ ถูกถามทุกคำขอเหมือนรอบเครื่อง** (เฉพาะรถ CAN; ถ้ามีทั้งสองค่าบนจอจะถามแป้นคันเร่งก่อน): ตัวจำลอง หน้าหลัก 226 → **68 ms**, หน้า DATA 338 → **68 ms** แลกกับค่าอื่นที่อยู่บนจอ (โหลด, MAP, อุณหภูมิ ฯลฯ) รีเฟรชช้าลง: หน้าหลัก 225 → ~305 ms, หน้า DATA 338 → ~474 ms (ถ้าต้องการให้ค่าไหนเร็วกว่านี้ ให้เปลี่ยนช่องบนจอให้เหลือเท่าที่ดู; K-line ไม่เปลี่ยน)
- **แก้ข้อบกพร่องใน v1.0.10**: ถ้าบนจอมี CRP แต่ ECU ประกาศว่ามี PID แรงดันรางแต่ไม่ตอบ (PID 23/59) เกจจะถามซ้ำทุกคำขอจนเลิกใช้คำสั่งรวมแล้วตกไปโหมดถามทีละค่า (ตัวจำลอง: รอบ 68 → 190 ms, ค่าอื่นช้าลงมาก) ตอนนี้ข้าม PID ที่ไม่ตอบไปพักหนึ่ง เหมือนค่าอื่น (รอบยังอยู่ที่ 68 ms)
- หน้าจออื่น ๆ ไม่เปลี่ยน: ภาพหน้าหลักตอนรอบนิ่งเหมือน v1.0.10 ทุกพิกเซล
- เครื่องที่ลง v1.0.0–v1.0.10 อัปเดตผ่าน Wi-Fi ได้เลย (SETUP → UPDATE)
- ⚠️ **ไม่ได้ทดสอบกับรถและบอร์ดจริง** ตัวเลขทั้งหมดมาจากตัวจำลองบนคอมพิวเตอร์ (สมมติอะแดปเตอร์ตอบ ~45 ms/คำสั่ง) ความเร็วจริงถูกจำกัดโดย ECU และอะแดปเตอร์ — ดูเวลารีเฟรชรอบจริงของรถคุณที่หน้า ECU info (บรรทัด Protocol) เวลาวาดจอจริงของบอร์ดยังไม่ได้วัด

## ของใหม่ใน v1.0.10 (CRP ตรงขึ้น: ปรับเทียบกับมิเตอร์ได้ + ถามค่าถี่ขึ้น)
- **CRP อ่านจาก ECU ผ่าน OBD-II** (ตั้งแต่ v1.0.9): แรงดันรางหัวฉีดจาก PID 0x23 (หรือ 0x59) ที่ ECU วัดจากเซนเซอร์ท้ายรางอยู่แล้ว ไม่ต้องต่อสายเพิ่ม แล้วแสดงเป็นโวลต์เหมือนเดิม (หน้าหลัก, DATA → CRP log) ตามเส้น `V = V0 + (4.50 − V0) × MPa ÷ ช่วงเต็มสเกล`
- **ค่าเริ่มต้นปรับใหม่เป็นช่วงเต็มสเกล 180 MPa ที่ 4.50 V** (เซนเซอร์ 1800 bar) แทน 200 — จากค่าที่คุณวัดได้: มิเตอร์ 1.31 V แต่เกจเดิมขึ้น 1.24 V (ที่ ~37 MPa) สเกลใหม่ได้ ~1.32 V ใกล้ของจริงขึ้น (ค่านี้ใช้กับทุกเครื่องหลังอัปเดต; ค่า 200 ที่เคยบันทึกไว้จะถูกแทนที่)
- **หน้าปรับเทียบใหม่ SETUP → More → CRP sensor → ปุ่ม Calibrate**
  - **Full scale** (50–400 MPa) / **Volts at 0 MPa** (0.00–2.00 V, ค่าเริ่มต้น 0.50) / **Pressure trim** (50–150 %, คูณค่า MPa จาก ECU ให้ตรงกับเครื่องมืออื่น) / **Rail PID** (Auto = 0x23 ถ้าไม่มีใช้ 0x59, หรือบังคับ 0x23 / 0x59)
  - **ตั้งตามมิเตอร์ (Meter reading + ปุ่ม Match meter)**: ติดเครื่องให้มีแรงดันราง (> 5 MPa) → วัดโวลต์ที่สายสัญญาณเซนเซอร์ด้วยมิเตอร์ → ตั้งแถว "Meter reading" ให้เท่ากับค่าที่วัด (ตอนเปิดหน้าจะเริ่มที่ค่าที่เกจโชว์อยู่) → กด **Match meter** เกจจะคำนวณ Full scale ให้เองให้ตรงกับมิเตอร์ ณ จุดนั้น (กรณีของคุณ: 37 MPa ที่ 1.31 V → ได้ ~183 MPa)
  - แถบกลางล่างแสดงสดว่า "xx.x MPa = x.xx V" ตามค่าที่ตั้งไว้ เพื่อดูผลขณะปรับ; ปุ่ม **Defaults** คืนทุกค่า
  - ⚠️ วัดจุดเดียวแยกไม่ออกว่าคลาดเพราะ "โวลต์ที่ 0 MPa" หรือ "ความชัน" — เครื่องเลือกปรับความชัน (Full scale) ให้ ถ้าวัดอีกจุดที่รอบ/โหลดสูงกว่าแล้วยังไม่ตรง ให้ปรับ **Volts at 0 MPa** เพิ่ม แล้ว Match meter ใหม่
- **ถามแรงดันรางถี่ขึ้น (ค่าตามทัน กระโดดน้อยลง)** เมื่อหน้าจอแสดง CRP (หน้าหลัก, หน้า CRP sensor / Calibrate, CRP log): บน CAN ถามพ่วงในคำขอเดียวกับรอบ/ความเร็วทุกครั้ง; บน K-line ถามเป็นช่องของตัวเองทุกรอบ ตัวจำลอง: CAN 225 → **68 ms**, K-line KWP 2,660 → **465 ms**, ISO 9141 5,400 → **950 ms** — แลกกับค่าอื่นบน K-line รีเฟรชช้าลง (13 ค่าวนครบ ~5.7 วินาที จาก ~4.0) เฉพาะตอนที่หน้าจอแสดง CRP; หน้าอื่นไม่เปลี่ยน รอบเครื่อง/ความเร็วเท่าเดิม
- เครื่องที่ลง v1.0.0–v1.0.9 อัปเดตผ่าน Wi-Fi ได้เลย (SETUP → UPDATE)
- ⚠️ **ไม่ได้ทดสอบกับรถและบอร์ดจริง** (ทดสอบในตัวจำลองบนคอมพิวเตอร์เท่านั้น) ค่าโวลต์ยังเป็นค่าคำนวณจากแรงดันที่ ECU รายงาน ไม่ใช่แรงดันที่วัดจากสายเซนเซอร์; ความแม่นขึ้นกับที่ ECU รายงานและสเกลที่ตั้ง ตัวเลขความถี่เป็นของตัวจำลอง

## ของใหม่ใน v1.0.7 (K-line ไวขึ้น ใกล้เรียลไทม์)
- **K-line (ISO 9141 / KWP) ถามรอบเครื่องถี่ขึ้น 2 เท่า**: เดิมรอบเครื่องได้คิวทุก 4 คำขอ ตอนนี้ทุก 2 คำขอ (ลำดับ รอบ → ความเร็ว → รอบ → ค่าอื่น) ในตัวจำลอง KWP จาก 466 → **~230 ms**, ISO 9141 จาก 965 → **~470 ms**
- **K-line ลองขอ "รอบ + ความเร็ว" ในคำสั่งเดียว**: มาตรฐาน OBD-II รับรองเฉพาะ CAN แต่ ECU บางรุ่นก็ตอบ — ถ้ารถรับ ความเร็วจะอัปเดตเท่ารอบ (ถี่ทั้งคู่); ถ้ารถไม่ตอบ/ตอบแค่ค่าแรก เครื่องเลิกใช้เองภายใน ~1 วินาทีแรกและถามความเร็วแยก (ไม่ต้องตั้งค่าอะไร)
- **รถ CAN ที่ไม่รับคำสั่งรวม** (อะแดปเตอร์/รถบางรุ่น): รอบเครื่องเร็วขึ้น 2 เท่าเช่นกัน (ในตัวจำลอง 226 → ~115 ms)
- **CAN ปกติ** ใกล้เพดานของอะแดปเตอร์อยู่แล้ว (รอบ + ความเร็ว + อีก 4 ค่า ในคำสั่งเดียว ~68 ms ในตัวจำลอง) จึงไม่เปลี่ยน; **การแสดงผลไม่มีการหน่วง/เฉลี่ยค่า** (ค่าขึ้นจอทุกเฟรม 30 เฟรม/วินาที)
- แลกกับ: บน K-line ค่าอื่นที่ไม่ใช่รอบ/ความเร็ว (อุณหภูมิ ฯลฯ) รีเฟรชช้าลงราว 1.5 เท่า (ตัวจำลอง: 13 ค่าวนครบทุก ~6 วินาที จากเดิม ~4 วินาที) และสถานะไฟเตือนเครื่องยนต์ (MIL) ตรวจทุก 4 วินาที (เดิม 2 วินาที) บน K-line
- เครื่องที่ลง v1.0.0–v1.0.6 อัปเดตผ่าน Wi-Fi ได้เลย (SETUP → UPDATE)
- ⚠️ **ตัวเลขทั้งหมดมาจากตัวจำลองบนคอมพิวเตอร์ ไม่ได้วัดกับรถจริง** (สมมติอะแดปเตอร์ตอบ 110 / 220 ms ต่อคำสั่งสำหรับ KWP / ISO 9141) เพดานจริงถูกกำหนดโดยตัว ECU และอะแดปเตอร์ — K-line ถามได้แค่ราว 4–9 คำสั่งต่อวินาที — ดูเวลารีเฟรชรอบเครื่องจริงของรถคุณที่ **หน้า ECU info (บรรทัด Protocol)**

## ของใหม่ใน v1.0.4 (กลับหัวจอ + มอเตอร์ไซค์ต่อเองอัตโนมัติ)
- **กลับหัวหน้าจอได้**: SETUP → แถว **จอภาพ (Screen)** → เลือก **ปกติ / กลับหัว** สำหรับติดตั้งบอร์ดกลับด้าน หมุนภาพ 180° และ **หมุนตำแหน่งสัมผัสตามด้วย** (แตะตรงไหนก็ทำงานตรงนั้น ไม่ต้องคาลิเบรตใหม่) จำค่าไว้ตอนปิดเครื่อง — หน้า SETUP จึงมี 4 แถวแล้ว (ภาษา / ไฟเตือนรอบ / สีหน้าจอ / จอภาพ)
- **ไม่ต้องกดเลือกอะแดปเตอร์เอง**: ถ้ายังไม่เคยเลือกอะแดปเตอร์ เครื่องจะค้นหา Bluetooth เองหลังเปิดเครื่อง ~2.5 วินาที (ครั้งแรกใช้เวลา ~15 วินาที) แล้วต่อให้ทันทีถ้าเจออะแดปเตอร์ OBD **ตัวเดียว** หรือตัวที่สัญญาณแรงกว่าตัวอื่นชัดเจน (เกิน 8 dB) แล้วจำไว้ใช้ครั้งต่อไป — ถ้าไม่เจอจะลองใหม่ทุก 25 วินาที; ถ้ามีอะแดปเตอร์ใกล้เคียงกันหลายตัวจะไม่เดา ให้เลือกเองที่ SETUP → BLUETOOTH; ไม่เปลี่ยนอะแดปเตอร์ที่เคยเลือกไว้ และหยุดค้นหาเองขณะเปิดหน้า BLUETOOTH
- **มอเตอร์ไซค์ Honda ตรวจพบเองจาก VIN**: พอเชื่อมต่อแล้วอ่านเลขตัวถัง ถ้าเป็นกลุ่มมอเตอร์ไซค์ เครื่องจะสลับเป็นโปรไฟล์มอเตอร์ไซค์เอง (มาตรรอบ 12,000, ตาราง CRP/AFR ทีละ 2,000 รอบ, ถังเริ่มต้น 6 ลิตร, รอบเตือน 8,500 — ปรับได้ที่ SETUP) และ **จำรุ่นที่คุณเลือกไว้ตามรหัส VIN ของรถคันนั้น** (ตัวที่ 4–8) ครั้งต่อไปใส่รุ่น/ขนาดถัง/รอบเตือนให้เองโดยไม่ต้องเลือกซ้ำ; ถ้าเลือกเป็นรถยนต์เองไว้ จะไม่ถูกเปลี่ยน; ถ้านำไปต่อรถยนต์ เครื่องจะเอาค่ามอเตอร์ไซค์ออกให้
- เพิ่ม: ขนาดถังตั้งได้ต่ำถึง **3 ลิตร** (เดิมต่ำสุด 10 และรุ่นมอเตอร์ไซค์ที่ถังเล็กกว่า 10 ลิตรถูกรีเซ็ตเป็น 44 ลิตรหลังรีสตาร์ท — แก้แล้ว)
- เครื่องที่ลง v1.0.0–v1.0.3 อัปเดตผ่าน Wi-Fi ได้เลย (SETUP → UPDATE)
- ⚠️ **ยังไม่ได้ลองกับบอร์ด/รถ/Bluetooth จริง**: ทดสอบบนคอมพิวเตอร์ด้วยตัวจำลองอะแดปเตอร์ ELM327 และ Bluetooth (การค้นหา/เลือกอัตโนมัติ, ตรวจมอเตอร์ไซค์จาก VIN, การจำรุ่น, การกลับหัวและสัมผัส) การกลับหัวอาศัยโหมดหมุนจอ 180° ของ TFT_eSPI ซึ่งใช้ได้กับจอทั้งสองแบบในทางทฤษฎี แต่ยังไม่ได้ดูบนจอจริง; ตาราง "รหัส VIN → รุ่นมอเตอร์ไซค์ Honda" ไม่ได้ใส่มาให้ เพราะยังไม่มีข้อมูลที่ยืนยันได้ — ถ้ามีเลข VIN จากรถจริงส่งมาได้ จะเพิ่มให้เครื่องรู้รุ่นเองตั้งแต่ครั้งแรก

## ของใหม่ใน v1.0.3 (ลดหน่วง ตอบสนองไวขึ้น ตรวจค่าให้ถูกต้อง)
- **อ่านค่ารถเร็วขึ้น**: รถ CAN (รุ่นใหม่ส่วนใหญ่) ขอ **รอบ + ความเร็ว + อีก 4 ค่า ในคำสั่งเดียว** (OBD-II ให้ขอได้สูงสุด 6 ค่าต่อคำสั่ง) และใส่ตัวเลข "จำนวนคำตอบ" ท้ายคำสั่ง ทำให้อะแดปเตอร์ไม่ต้องรอเวลาเผื่อหลังรถตอบแล้ว — ถ้ารถหรืออะแดปเตอร์ตัวไหนไม่รับ เครื่องถอยกลับไปถามทีละค่าเองอัตโนมัติ (ไม่ต้องตั้งอะไร)
- **ค่าที่รถไม่ตอบไม่ถ่วงค่าอื่น**: ค่าที่อยู่ในรายการ PID แต่ไม่เคยตอบ (ตอบ NO DATA) จะถูกข้ามไป 30 รอบแล้วลองใหม่ แทนที่จะรอ timeout ทุกรอบ
- **ขึ้นค่าแรกเร็วขึ้น**: อ่านเลขตัวถัง (VIN) หลังจากมีค่าขึ้นจอแล้ว ไม่ขวางตอนเชื่อมต่อ; ต่อใหม่หลังหลุดเร็วขึ้น (รอ 0.3 วินาที แทน 1 วินาที / ลองต่ออะแดปเตอร์ใหม่ทุก 1.5 วินาที แทน 3)
- **จอรีเฟรช 30 เฟรม/วินาที** (เดิม ~12) และ **ค่า CRP (โวลต์) อ่านทุก 20 ms** กรองสั้นลง (เดิมอ่านทุก 100 ms) ตามสัญญาณทัน
- **หน้า ALL PIDS**: 5 แถวที่เห็นบนจอถูกอ่านก่อน (เดิมอ่านวนทุกค่าเท่ากันหมด ทำให้แถวที่เห็นรีเฟรชช้ามาก)
- **ตรวจความถูกต้องของค่า**: ตรวจสูตรแปลงค่าทุก PID (55 ตัว) เทียบสูตรมาตรฐาน SAE J1979 แล้วตรงทุกตัว; ค่า "ใช้ไม่ได้" ที่ ECU บางรุ่นส่งเป็น 0xFFFF (รอบ >16,000, MAF, แรงดัน, อัตราสิ้นเปลือง, แลมบ์ดา) จะไม่แสดงเป็นตัวเลข (ขึ้น `--`) แทนที่จะโชว์ค่าเพี้ยน; ค่ารอบ/ความเร็วเก่าเกิน 3 วินาที (เดิม 8) ขึ้น `--` ทันทีถ้าสายหลุด
- **หน้า ECU info**: บรรทัด Protocol แสดงเวลารีเฟรชรอบจริงของรถคันนั้น เช่น `CAN 11/500  68 ms` (วัดจากเครื่องจริงตอนใช้งาน) เอาไว้เทียบว่าอะแดปเตอร์/รถตอบเร็วแค่ไหน
- เครื่องที่ลง v1.0.0–v1.0.2 อัปเดตผ่าน Wi-Fi ได้เลย (SETUP → UPDATE)
- ⚠️ **ตัวเลขความเร็วที่ได้มาจากการจำลอง ไม่ได้วัดกับรถจริง**: ทดสอบกับตัวจำลอง ELM327 บนคอมพิวเตอร์ (สมมติเวลาตอบของอะแดปเตอร์ 45 ms ต่อคำสั่ง) รอบ/ความเร็วรีเฟรชทุก ~68 ms เทียบกับ ~433 ms ของ v1.0.2 (เร็วขึ้นราว 6 เท่า) รถ K-line (รถเก่า) ถามได้ทีละค่า เร็วขึ้นราว 1.5 เท่า (700 → 466 ms ที่สมมติ 110 ms/คำสั่ง); ค่าจริงขึ้นกับอะแดปเตอร์และ ECU ของแต่ละคัน และความเร็ว SPI ของจอคงเดิมโดยตั้งใจ (40 MHz — เคยลองสูงกว่านี้แล้วภาพเพี้ยนจนกู้ไม่ได้ผ่านอัปเดต)

   - `bin-cyd` สำหรับบอร์ด 1 USB
   - `bin-cyd_st7789` สำหรับบอร์ด 2 USB
   แตกซิปแล้วใช้ไฟล์ `smart-gauge-…-full.bin`

## ออกเวอร์ชันใหม่ให้ลูกค้า (สำหรับเจ้าของ)
1. แก้เลขเวอร์ชันใน `main.cpp` บรรทัด `#define FW_VERSION "v1.0.19"` (เช่น `v1.0.20`) พร้อมแก้โค้ดที่ต้องการ แล้ว Commit
2. ออก Release ได้ 2 วิธี (เลือกอย่างใดอย่างหนึ่ง):
   - ใส่คำว่า `[release]` ในข้อความ commit บน main → Actions บิลด์แล้วสร้างแท็กและ Release ให้เองตามเลขใน FW_VERSION (ถ้าบิลด์ไม่ผ่านจะไม่ออก Release)
   - หรือ GitHub → **Releases → Draft a new release** → ช่อง *Choose a tag* พิมพ์ `v1.0.16` (ต้องตรงกับ FW_VERSION เป๊ะ) → **Create new tag** → **Publish release**
3. ระบบ Actions บิลด์แล้วแนบไฟล์เข้า Release ให้เอง: `firmware_cyd.bin`, `firmware_cyd_st7789.bin` (ใช้อัปเดตผ่าน Wi-Fi) และ `smart-gauge-…-full.bin` (ใช้แฟลชผ่าน USB) — รอจนขึ้นครบ (ประมาณ 5–8 นาที)
4. ลูกค้าเปิดเครื่อง → SETUP → UPDATE ก็จะเห็น "New version available"
- **repo ที่เก็บ Release ต้องเป็น Public** เครื่องลูกค้าไม่มี token จึงอ่าน repo ส่วนตัวไม่ได้ (ตั้งชื่อ repo/เจ้าของที่ `UPD_OWNER` / `UPD_REPO` ใน `platformio.ini`, ค่าเริ่มต้น `preay25715-a11y/JetSmartGaugeCAR`)
- อย่าลบไฟล์ใน Release ที่เป็นรุ่นล่าสุด และอย่าติ๊ก Pre-release (เครื่องอ่านเฉพาะรุ่นล่าสุดที่ไม่ใช่ pre-release)

## วิธีอัปเดตของลูกค้า (ผ่าน Wi-Fi)
1. จอดรถ ดับเครื่อง → SETUP → **UPDATE** → **Start update mode** (เครื่องรีสตาร์ทเข้าโหมดอัปเดต — Wi-Fi มีเฉพาะโหมดนี้)
2. ครั้งแรก: **Wi-Fi** → เลือกเครือข่าย (ฮอตสปอตมือถือใช้ได้) → พิมพ์รหัสผ่าน → **Connect** (เครื่องจำเครือข่ายไว้ ครั้งต่อไปต่อเอง)
3. เครื่องเช็คเวอร์ชันเอง ถ้าขึ้น **New version available** กด **Install update** → รอประมาณ 1–2 นาที **ห้ามปิดไฟ** → เสร็จแล้วรีสตาร์ทกลับเข้ามาตรวัดเอง
4. อยากออกโดยไม่อัปเดต กด **Back** (รีสตาร์ทกลับมาตรวัด)
- ถ้าอัปเดตไม่สำเร็จ (ไฟดับ/สัญญาณหลุด) ตัวอัปเดตยังอยู่ครบ เปิดเครื่องแล้วจะเข้าโหมดอัปเดตให้ลองใหม่ได้ ไม่ต้องแฟลชสาย
- ตัวอัปเดตเอง (ส่วนที่ 2 ของแฟลช) ไม่ถูกอัปเดตผ่าน Wi-Fi ถ้าวันหน้าต้องแก้ จะออกไฟล์ `smart-gauge-…-full.bin` ให้แฟลชผ่าน USB

## เปิดเครื่องครั้งแรก
- จะขึ้นโลโก้ 7 วินาที **ถ้าพื้นหลังเป็นสีขาว ให้แตะจอ 1 ครั้ง** จะกลับเป็นสีดำและจำค่าไว้ (เปลี่ยนทีหลังได้ที่ SETUP → COLORS STD/INV)
- ถ้าสีเพี้ยน (น้ำเงินกลายเป็นส้ม/แดง) ให้แฟลชไฟล์ของบอร์ดอีกแบบแทน (cyd ↔ cyd_st7789)
- ไม่ต่อรถ = ค่าต่างๆ ขึ้น `--` จนกว่าจะต่ออะแดปเตอร์/บอร์ด K-line ถ้าอยากทดสอบหน้าจอบนโต๊ะโดยไม่มีรถ ให้เปิด **DEMO** (SETUP → MORE → ปุ่ม **DEMO** แถวล่างขวา — เพิ่มกลับมาใน v1.0.18; ดูหัวข้อ "ของใหม่ใน v1.0.18")
- โหมดเริ่มต้นหลังแฟลชใหม่คือ **รถยนต์ (Bluetooth)**; ถ้าใช้กับมอเตอร์ไซค์ Honda ให้สลับเป็น K-line (SETUP → BLUETOOTH → Honda K-line) ครั้งเดียว เกจจำไว้

## ต่อกับรถยนต์ (โหมดรถ, ELM327)
1. เสียบอะแดปเตอร์แล้วเปิดเครื่องเฉยๆ ก็ได้ — ถ้ายังไม่เคยเลือกอะแดปเตอร์ เครื่องหาและต่อให้เอง (v1.0.4); หรือเลือกเอง: SETUP → ปุ่ม **BLUETOOTH** → ค้นหา → แตะชื่ออะแดปเตอร์ของคุณ (เช่น KW902 / OBDII)
2. เสียบอะแดปเตอร์ที่รถ เปิดสวิตช์ (ON หรือสตาร์ท) รอสถานะ CONNECTED — จำอะแดปเตอร์ไว้ ครั้งต่อไปต่อเอง; PIN ลองให้เองตามลำดับ 1234 / 0000 / 6789 / 1111
3. ชื่อยี่ห้อ/รุ่นบนแถบหัวของหน้าหลักขึ้นเองจาก VIN (Mazda ขึ้นชื่อรุ่นเอง, ยี่ห้ออื่นขึ้นชื่อยี่ห้อ) ถ้าอยากให้ตรงรุ่นให้เลือกที่ SETUP → VEHICLE (ตั้งขนาดถังและรอบเตือนให้ตรงรุ่นด้วย)
4. ถ้าต่อไม่ติด: SETUP → MORE → **PROTOCOL** ลองเลข 6 (CAN รถรุ่นใหม่) หรือ 3 / 4 / 5 (รถเก่า) แล้วรอ 2 วินาที จะต่อใหม่เอง; AUTO คือให้อัตโนมัติ

## ต่อกับมอเตอร์ไซค์ (โหมด K-line)
1. สลับโหมด: SETUP → ปุ่มซ้ายสุด → ปุ่ม **Honda K-line** (ครั้งเดียว เกจจำไว้)
2. ต่อสายตามตารางในหัวข้อ v1.0.13 ด้านบน (ปลั๊ก DLC 6 พิน: D = K-line, F = +12 V ผ่านฟิวส์ 1 A, A = GND → บอร์ด K-line → IO22 (รับ, ผ่านตัวแบ่งแรงดัน) / IO27 (ส่ง) ของ CYD)
3. เปิดกุญแจ ON (ไม่ต้องสตาร์ทก็ได้) — เกจปลุก ECU เอง รอสถานะ **CONNECTED** ที่แถบหัวหน้าหลัก (เขียน K-LINE / HONDA); ดูตารางดิบและค่าถอดรหัสที่ SETUP → **K-LINE**
4. ชื่อบนแถบหัวขึ้น "HONDA BIKE" เอง ถ้าอยากให้ตรงรุ่น (ขนาดถัง/รอบเตือน/ขนาดเครื่อง) ให้เลือกที่ SETUP → VEHICLE → Honda
5. ถ้าต่อไม่ติด: ดูข้อแนะนำการเช็กใน v1.0.13 (ไฟ +12 V, สาย K, ตัวแบ่งแรงดัน, บอร์ดต้องไม่กลับสัญญาณ)

## ต่อกับแอป Jet Honda APP (ทั้งสองโหมด)
ต่อสาย USB ของเกจเข้าเครื่องที่เปิดแอป (คอม: Web Serial / Android: OTG) แล้วเลือก Smart Gauge (BLE / USB) → USB ในแอป เกจตอบ PING, SENSORS, LIVE, LOG_GET ได้ทันที; คำสั่งสาย K (WAKE/TXRX/SENSE) ใช้ได้เมื่อต่อบอร์ด K-line — รายละเอียดและรูปแบบข้อมูลใน v1.0.15 ด้านบน (ไม่ต้องกดอะไรบนเกจ; แถบบนขวาขึ้น `APP` ตอนแอปคุยอยู่)

## การใช้งานหลัก
- หน้าหลัก: แตะช่องค่าทั้ง 6 ช่องเพื่อเปลี่ยนค่าที่แสดง (จำไว้), แตะกลางมาตรหรือแถบล่างเพื่อสลับ — โหมดรถ: ความเร็ว → CRP (โวลต์) → AFR; โหมด K-line: ความเร็ว ↔ ระยะทริป
- DATA — โหมดรถ 4 ปุ่ม: **MAIN** (16 ช่องค่า เบนซิน/ดีเซล) / **ALL PIDS** / **CRP log** / **AFR log**; โหมด K-line 2 ปุ่ม: **MAIN** (16 ช่อง ชุด Honda: รอบ ความเร็ว คันเร่ง MAP น้ำ อากาศเข้า แบต timing หัวฉีด ระยะทาง ความเร็วเฉลี่ย เวลา รอบ/ความเร็ว/น้ำสูงสุด แบตต่ำสุด) / **ALL PIDS**. ปุ่ม Reset ในหน้า log ล้างตารางที่ดูอยู่ (เก็บในหน่วยความจำ หายเมื่อปิดเครื่องหรือเปลี่ยนรุ่นรถ — ดึงเข้าแอปด้วย LOG_GET); ค่าทริป/ค่าสูงสุดในช่อง DATA ของโหมด K-line เก็บในหน่วยความจำเช่นกัน
- GRAPH กราฟย้อนหลัง, TRIP ระยะทาง-อัตราสิ้นเปลือง(ประมาณ)-PEAKS, ECU = รหัส ECU/โปรโตคอลและเวลารีเฟรช; โหมดรถ: CODES อ่าน/ลบรหัสเสีย (ลบต้องกด 2 ครั้ง), STATUS = มอนิเตอร์/Freeze frame/ข้อมูล ECU; โหมด K-line: หน้า CODES/มอนิเตอร์/Freeze ยังอ่านผ่าน K-line ไม่ได้ (ขึ้นข้อความแจ้ง)
- ดับเครื่องแล้วจะขึ้นหน้าจอจอดรถ (ปิดได้ที่ SETUP → MORE), มีเตือนน้ำร้อน/น้ำมันเครื่องร้อน/แบตต่ำ/ไฟ Check Engine; SETUP → MORE → ปุ่ม **Colourful** เปิด/ปิดสีสัน

## ข้อจำกัดที่ควรรู้
- โหมดรถ: มอเตอร์ไซค์ Honda ส่วนใหญ่ไม่มีพอร์ต OBD-II มาตรฐาน (ใช้ขั้วต่อ HDS ของ Honda) อะแดปเตอร์ ELM327 ทั่วไปจึงอ่านไม่ได้ — ใช้โหมด K-line แทน; โหมด K-line อ่านได้เฉพาะรถที่ ECU คุย K-line แบบ Honda (ตาราง 11) ผ่านบอร์ด K-line — ตำแหน่งไบต์ของตารางมาจากแอป Jet Honda APP/ชุมชนและยังไม่ยืนยันกับทุกรุ่น; ค่าที่ไม่มี (น้ำมันเครื่อง, MAF, AFR, รหัสเสีย ฯลฯ) ไม่แสดง
- AFR log ใช้ได้เฉพาะรถที่ ECU ตอบค่า lambda/wideband (PID 24 / 44); CRP log เฉพาะรถที่ตอบ PID 23 / 59 — ไม่ตอบ = ตารางว่าง; โหมด K-line ไม่มี AFR/CRP
- ความเร็วในการอ่านค่าวัดจากตัวจำลองเท่านั้น (ELM327 มีระบบถอยกลับอัตโนมัติ, K-line ~26 ตาราง/วินาทีในตัวจำลอง) ของจริงขึ้นกับ ECU/อะแดปเตอร์ — ดูเวลาจริงที่หน้า ECU และ K-line และแจ้งรุ่นรถ/อะแดปเตอร์ได้ถ้าค่าขึ้นช้า
- การรู้ว่าเป็นเบนซินหรือดีเซลต้องให้ ECU ตอบ (OBD-II PID 01 / 51); รถที่ไม่ตอบจะใช้ตามรุ่นที่เลือกไว้ (ตัวอักษรสีเทา)
- ระบบอัปเดต Wi-Fi ยังไม่ได้ทดสอบบนบอร์ดจริง/GitHub จริง (ทดสอบตรรกะและหน้าจอบนคอมพิวเตอร์เท่านั้น) และไฟล์เฟิร์มแวร์อาจใหญ่เกินช่องในแฟลช 4 MB — ขั้นตอน Actions จะแจ้ง error ขนาดไฟล์ให้ชัดเจนถ้าเกิดขึ้น
- ตอนโหลดอัปเดตเครื่องตรวจความถูกต้องด้วย SHA-256 ของไฟล์ที่ GitHub แจ้ง แต่ไม่ได้ตรวจใบรับรอง TLS ของเซิร์ฟเวอร์ (บอร์ดไม่มีที่เก็บใบรับรอง)
- ยังไม่ได้ลองกับบอร์ดจริง รถจริง และแอปจริง: คอมไพล์และวาดภาพหน้าจอทุกหน้าบนคอมพิวเตอร์เทียบกับพรีวิวแล้ว แต่ไม่ได้รันบนชิป ESP32 จริง (อาจมี error ตอนบิลด์จริงบน GitHub ให้ส่งข้อความ error มาได้) ถ้าเจออะไรผิดปกติบอกได้เลย
- ค่าที่รถไม่รองรับจะแสดง `--` (บางรุ่นไม่มีอุณหภูมิน้ำมันเครื่อง, บูสต์, AFR ฯลฯ) ค่าเฉพาะยี่ห้อ (เช่น อุณหภูมิน้ำมันเกียร์) ยังไม่รวม ใช้ค่ามาตรฐาน OBD-II เท่านั้น (K-line: ค่าจากตาราง 11)
- คำอธิบายรหัสเสียเป็นภาษาอังกฤษ; ข้อความภาษาไทยบางจุดอาจชิดกันเล็กน้อย
